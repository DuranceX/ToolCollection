# 部署到 tools.starnight.top（GitHub Pages）

推送到 `main` 自动构建并发布，不需要服务器。

workflow 在 `.github/workflows/deploy.yml`，流程是：
`npm ci` → `npm run check`（类型检查 + 236 项测试 + 3000 组 fuzz）→ `npm run build` → 发布 `dist/`。

**check 失败不会发布**，坏版本上不了线。

---

## 一次性设置

以下三步只做一次，之后推送就自动部署。

### 1. 仓库开启 Pages

GitHub 仓库 → **Settings** → **Pages** → **Build and deployment** → Source 选 **GitHub Actions**。

注意不是选 "Deploy from a branch"，那是旧方式。

### 2. Cloudflare 加 DNS 记录

域名在 Cloudflare 托管，所以在 Cloudflare 控制台加（不是腾讯云 DNS）：

```
类型:   CNAME
名称:   tools
目标:   DuranceX.github.io
代理:   已代理（橙色云朵）
TTL:    自动
```

橙色云朵和 `mail.` / `file.` 保持一致，国内走 Cloudflare 节点，比直连 GitHub 稳。

生效后确认：

```bash
dig +short tools.starnight.top
```

### 3. 仓库里填自定义域名

GitHub 仓库 → Settings → Pages → **Custom domain** 填 `tools.starnight.top` → Save。

仓库里已经有 `public/CNAME` 文件（内容就是这个域名），构建时会自动进 `dist/` 根目录，所以这一步 GitHub 通常会自动识别。

勾上 **Enforce HTTPS**。首次签发证书要等几分钟。

## 几个要留意的点

**便签数据绑定在域名上。** 存在 localStorage、按 origin 隔离。所以：

- `tools.starnight.top` 的便签和 `mail.` / `file.` 不共享，这是对的
- 如果先在 `DuranceX.github.io/ToolCollection/` 上存过便签，绑自定义域名后看不到旧数据——origin 变了。需要先用工具里的「导出」存一份 JSON，再到新域名「导入」
- 换浏览器、换设备也看不到，这是当初选 localStorage 的既定取舍

**Cloudflare 缓存可能让更新不立即可见。** Pages 发布完但页面还是旧的，去 Cloudflare 控制台 → Caching → **Purge Everything**。或者把 `tools.starnight.top` 的缓存规则设成 Bypass，开发期更方便。

**资源路径是相对的**（`./assets/`、`../../assets/`），所以根路径和子路径都能跑，`vite.config.ts` 里的 `base: "./"` 不用改。

**GitHub Pages 是纯静态托管**，不能配 nginx 那种自定义响应头。缓存策略由 Pages 自己决定（HTML 短缓存、带哈希的资源长缓存），行为和我们手写的 nginx 配置基本一致，不用额外处理。

**仓库必须是 public**，或者有 GitHub Pro。免费账号的私有仓库不能用 Pages。
